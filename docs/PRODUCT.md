# DevBoard — 产品文档

## 一句话定位

AI 驱动的项目管理工具。CLI + Skill 让 AI agent 自动管理任务/需求/Bug，人通过 TUI 查看和调整。

## 解决什么问题

AI agent 需要一个结构化的项目管理工具来追踪任务进度。现有的问题：

1. **AI 缺少项目管理接口** — AI 能写代码，但没有结构化的任务管理系统来追踪进度
2. **信息散落各处** — 任务在 Jira，文档在 Notion，AI 需要频繁切换上下文
3. **工时记录缺失** — AI 工作没有时间维度，无法回答"这个任务花了多久"
4. **现有工具太重** — 禅道/Jira 配置繁琐，不适合 AI agent 的自动化操作
5. **终端用户的需求** — 开发者习惯在终端里工作，不想频繁切换到浏览器

## 目标用户

**主要用户：AI agent**
- 通过 CLI + Skill 自动管理任务、记录工时、关联文档
- 结构化接口，适合自动化操作

**次要用户：人（开发者）**
- 通过 TUI 查看项目进度、手动调整任务
- 终端优先，不想切换到浏览器

## 竞品对比

| 竞品 | 做什么 | 不做什么 | DevBoard 的差异 |
|------|--------|---------|----------------|
| **禅道** | 完整项目管理（需求/任务/Bug/测试/甘特图） | 非终端/重/复杂/需服务器/AI 不友好 | DevBoard 轻量/终端/CLI/AI 驱动 |
| **Jira** | 企业级项目管理 | 非终端/重/商业/云端/AI 不友好 | DevBoard 免费/本地/CLI/AI 驱动 |
| **Notion** | 知识库 + 轻量数据库 | 非终端/云端依赖/AI 需要 API | DevBoard 本地优先/CLI/AI 原生 |
| **taskwarrior-tui** | 任务管理 | 无知识库/无时间追踪/无看板 | DevBoard 三合一 + AI 接口 |
| **Obsidian** | 知识库/笔记 | 无任务管理/非终端 | DevBoard 任务+知识一体 + AI 接口 |

## 核心功能

### 一、任务管理

#### 1.1 项目

- 创建/编辑/删除项目
- 每个项目独立的任务空间
- 项目概览：任务数、完成率、总工时

#### 1.2 里程碑

- 项目下的阶段划分（如 v0.1、v0.2）
- 设置目标截止日期
- 里程碑进度 = 关联任务完成率
- 状态：进行中 / 已完成

#### 1.3 任务类型

任务有三种类型，共享同一套状态流转和看板视图，但有不同的属性模板：

**Requirement（需求）**

| 属性 | 说明 |
|------|------|
| 标题 | 需求名称 |
| 用户故事 | 作为...我想...以便... |
| 验收标准 | 如何验证需求完成 |
| 优先级 | 低 / 普通 / 高 / 紧急 |
| 状态 | 待办 / 进行中 / 评审 / 完成 |
| 负责人 | 谁来做 |
| 截止日期 | 什么时候做完 |

**Task（任务）**

| 属性 | 说明 |
|------|------|
| 标题 | 任务名称 |
| 描述 | Markdown 格式的详细说明 |
| 优先级 | 低 / 普通 / 高 / 紧急 |
| 状态 | 待办 / 进行中 / 评审 / 完成 |
| 负责人 | 谁来做 |
| 截止日期 | 什么时候做完 |
| 标签 | 自定义分类标签 |

**Bug（缺陷）**

| 属性 | 说明 |
|------|------|
| 标题 | Bug 名称 |
| 描述 | Markdown 格式的详细说明 |
| 复现步骤 | 如何触发 Bug |
| 严重程度 | 轻微 / 一般 / 严重 / 致命 |
| 环境信息 | 操作系统、版本等 |
| 状态 | 待办 / 进行中 / 评审 / 完成 |
| 负责人 | 谁来修 |

操作：创建、编辑、删除、移动到里程碑。

#### 1.4 工作流

轻量但完整的工作流：需求拆分为任务，任务发现 Bug，三者通过关系链接。

```
需求 ──拆分──→ 任务 ──发现──→ Bug
 │              │              │
 └──────────────┴──────────────┘
         统一状态流
   待办 → 进行中 → 评审 → 完成
```

**关系类型**：
- 需求 → 任务：一个需求拆分为多个任务
- 任务 → Bug：任务执行中发现缺陷
- Bug → 任务：Bug 修复后关联到修复任务

**进度聚合**：
- 需求进度 = 关联任务的完成率
- 里程碑进度 = 关联需求/任务的完成率

**操作**：
- `devboard task link <id> --type requires --target <id>` 建立关系
- `devboard task unlink <id> --target <id>` 解除关系
- `devboard task graph <id>` 查看关系图

#### 1.5 状态流转

```
待办 → 进行中 → 评审 → 完成
 ↑                      │
 └─────── 重新打开 ──────┘
```

快捷键一键切换状态。

#### 1.6 子任务

- 任务可以拆分为子任务
- 子任务完成进度影响父任务
- 树形展示任务层级

#### 1.7 看板视图

四列看板，用键盘操作卡片：

```
┌──────────┐ ┌──────────┐ ┌──────────┐ ┌──────────┐
│ 待办     │ │ 进行中   │ │ 评审     │ │ 完成     │
│          │ │          │ │          │ │          │
│ ┌──────┐│ │ ┌──────┐│ │ ┌──────┐│ │ ┌──────┐│
│ │ 任务1 ││ │ │ 任务3 ││ │ │ 任务5 ││ │ │ 任务7 ││
│ └──────┘│ │ └──────┘│ │ └──────┘│ │ └──────┘│
│ ┌──────┐│ │ ┌──────┐│ │          │ │ ┌──────┐│
│ │ 任务2 ││ │ │ 任务4 ││ │          │ │ │ 任务8 ││
│ └──────┘│ │ └──────┘│ │          │ │ └──────┘│
└──────────┘ └──────────┘ └──────────┘ └──────────┘
```

- `h/l` 左右移动卡片
- `j/k` 上下选择
- `n` 新建卡片
- `Enter` 编辑卡片

#### 1.8 任务搜索

- 按关键词搜索标题和描述
- 按状态/优先级/负责人过滤
- 按时间范围过滤

### 二、时间追踪

#### 2.1 任务计时

- 选中任务按空格开始计时
- 再按空格停止
- 状态栏显示当前计时
- 自动记录到数据库
- **标记 actor**：CLI 操作通过 `--actor ai` 或环境变量 `DEVBOARD_ACTOR=ai` 指定；TUI 操作默认 `actor=human`

#### 2.2 手动补录

- 选中任务按 `t` 手动输入工时
- 支持格式：`2h 30m` / `1.5h` / `90m`
- 支持指定 actor：`--actor ai` 或 `--actor human`

#### 2.3 日工时汇总

每天结束时看到：
- 今天在每个任务上花了多少时间
- **AI 工时 vs 人工时**分别统计
- 总工时
- 按项目分组

#### 2.4 周/月报表

- 按项目统计工时
- 按任务统计工时
- **按 actor 统计**（AI / 人 / 合计）
- 时间分布可视化（柱状图）
- 导出 CSV / SVG / PNG

### 三、图表与可视化

所有图表支持两种展示方式：
- **TUI 展示**：终端内 ASCII 图表，快速预览
- **文件导出**：SVG / PNG / CSV，用于文档嵌入或分享

#### 3.1 甘特图

- 展示任务时间线：开始日期 → 结束日期
- 按里程碑分组，显示任务进度
- 支持依赖关系连线
- TUI：ASCII 时间线；导出：SVG / PNG

#### 3.2 燃尽图
- 展示剩余工时 / 任务数随时间的变化
- 按里程碑或项目维度
- TUI：ASCII 折线图；导出：SVG / PNG

#### 3.3 工时分布图

- 按项目/任务/日期维度的工时柱状图
- TUI：ASCII 柱状图；导出：SVG / PNG / CSV

#### 3.4 任务状态概览

- 饼图/条形图展示任务状态分布（待办/进行中/评审/完成）
- TUI：ASCII 饼图；导出：SVG / PNG

#### 3.5 里程碑进度

- 每个里程碑的完成率进度条
- TUI：ASCII 进度条；导出：Markdown 表格

#### 3.6 AI vs 人贡献图

- 展示每个任务/里程碑中 AI 和人的工时占比
- 饼图或堆叠柱状图
- TUI：ASCII 饼图；导出：SVG / PNG / CSV
### 四、文档（任务的扩展上下文）

文档是任务的补充说明，不是独立的知识库系统。

#### 4.1 任务关联文档

- 任务可以关联 Markdown 文档
- 文档是任务的扩展上下文（方案设计、会议记录、技术调研等）
- AI 处理任务时可以自动加载关联文档作为 context
- 文档存储在项目的 `docs/` 目录下

#### 4.2 Markdown 浏览

- 在终端内渲染预览 Markdown
- 支持：标题、列表、代码块、表格、链接
- 左边目录树，右边内容预览

#### 4.2.1 文档看板

四列看板，追踪文档生命周期：

```
┌──────────┐ ┌──────────┐ ┌──────────┐ ┌──────────┐
│ 草稿     │ │ 评审     │ │ 发布     │ │ 归档     │
│          │ │          │ │          │ │          │
│ ┌──────┐│ │ ┌──────┐│ │ ┌──────┐│ │ ┌──────┐│
│ │ 设计 ││ │ │ API  ││ │ │ 规范 ││ │ │ v1   ││
│ └──────┘│ │ └──────┘│ │ └──────┘│ │ └──────┘│
└──────────┘ └──────────┘ └──────────┘ └──────────┘
```

- `h/l` 左右移动文档卡片
- `j/k` 上下选择
- `n` 新建文档
- `Enter` 预览文档内容
- `e` 调用编辑器编辑

#### 4.3 树形目录

- 按目录结构组织文档
- 支持展开/折叠
- 支持创建/重命名/删除目录和文件

#### 4.4 创建/编辑文档

- 在终端内创建新文档
- 编辑已有文档（调用外部编辑器或内置编辑器）
- 自动保存

#### 4.5 全文搜索

- 搜索文档标题和内容
- 高亮匹配关键词
- 基于 SQLite FTS5，速度快

#### 4.6 标签系统

- 给文档打标签
- 按标签过滤文档
- 标签管理

#### 4.7 快速笔记

- 一键创建临时笔记
- 自动按日期归档
- 类似手机上的"快速备忘录"

## AI 工作流

DevBoard 的核心交互方式：**AI 通过 CLI + Skill 操作，人通过 TUI 查看/调整**。

### AI 的操作方式

AI 通过 CLI 命令与 DevBoard 交互：

```bash
# 任务管理
devboard task list                    # 列出所有任务
devboard task add "实现用户登录"       # 创建任务
devboard task update <id> --status done  # 更新状态
devboard task link <id> --doc docs/login-design.md  # 关联文档

# 工时记录
devboard time start <id> --actor ai      # 开始计时（显式指定 actor）
devboard time stop                    # 停止计时
devboard time log <id> --duration 2h 30m  # 手动补录
devboard time stats                   # 工时统计（按 actor 分组）
# 文档操作
devboard doc create "登录方案设计"     # 创建文档
devboard doc search "用户认证"         # 搜索文档
```

Skill 提供 AI 使用说明：参数格式、返回结构、最佳实践。

### 人的操作方式

人通过 TUI 查看项目进度、手动调整任务：

- 任务列表视图：查看所有任务，按优先级/状态排序
- 看板视图：拖拽卡片调整状态
- 时间统计：查看工时汇总和报表
- 文档浏览：查看关联文档

## 不做什么

- ❌ 不做审批流和阶段门禁（状态流转由 AI/人直接操作，不需要逐级审批）
- ❌ 不做代码编辑（那是 IDE 的事）
- ❌ 不做多人实时协同编辑（那是 Notion/Google Docs 的事）
- ❌ 不做自建云服务（同步走现有协议，不维护独立服务器）

## UI 风格

- 深色主题为主
- 三个主视图：任务列表 / 看板 / 文档
- 键盘操作优先，支持鼠标
- 状态用颜色区分：🟢 完成 / 🟡 进行中 / 🔴 紧急

## 数据存储

- SQLite 本地数据库
- 数据文件：`~/.devboard/data.db`
- 配置文件：`~/.devboard/config.toml`
- 文档文件：`~/.devboard/docs/`（Markdown 文件）
- 同步：支持多种同步方式（Git / WebDAV / Syncthing / SSH）
- 导出备份：支持导出到指定目录
