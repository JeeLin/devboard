# v0.2.0: 好用

## Context
v0.1.0 基础架构已完成，实现了项目、里程碑、任务的 CRUD 操作和基本的 CLI 界面。v0.2.0 将在此基础上添加时间追踪功能和看板视图，使工具更好用。
版本类型：minor（新功能）
里程碑起始 ref: c9981299c930244fde1dd44ec445883eb3250b3d

## 产品边界
本阶段做什么：
- 手动工时记录（智能时间解析、快速录入）
- 日工时汇总（按天统计 AI vs 人工时）
- 看板视图（TUI 中的 Kanban 板展示任务状态）
- 在现有 CLI 基础上扩展时间记录相关命令

本阶段不做什么：
- 文档功能（v0.3）
- 图表功能（v0.3）
- 同步功能（v0.5）

## 子任务详细设计

### 1 时间追踪模型：扩展 TimeEntry 模型和数据库迁移

- **功能目标**：完善时间追踪模型，支持记录工时时长、备注、日期等字段（纯手动记录模式，无 start/stop 计时器）
- **文件结构**：
  - `src/db/migration.rs`：添加时间追踪相关的表结构迁移
  - `src/models/time_entry.rs`：完善 TimeEntry 结构体和数据库映射
- **接口设计**：
  ```rust
  // 查询指定任务的时间记录
  pub fn get_time_entries_by_task(conn: &DbConn, task_id: i64) -> Result<Vec<TimeEntry>>;
  // 查询指定日期的工时汇总（按 actor 分组）
  pub fn get_daily_time_summary(conn: &DbConn, date: NaiveDate) -> Result<Vec<(String, i64)>>;
  ```
- **数据模型**：参考 DEVELOPMENT.md 中的 time_entries 表定义
- **测试标准**：`cargo test` 中的时间追踪相关测试通过
- **提交信息**：`feat: add time tracking model and migration`

### 2 时间追踪 CLI：task time 命令组（log/report）

- **功能目标**：提供命令行接口来手动记录工时、查看工时报表，支持智能时间解析
- **文件结构**：`src/cli/task.rs`：扩展 task 子命令，添加 time 子命令组
- **接口设计**：
  ```bash
  devboard task time log <task_id> <time> [--note "说明"]  # 手动记录工时
  devboard task time report [--date YYYY-MM-DD]  # 查看工时报表
  ```
  支持的时间格式：
  - `2h 30m` / `2.5h` / `150m`（标准格式）
  - `yesterday 3pm-5pm`（相对时间）
  - `2024-01-15 14:00-16:00`（绝对时间）
- **后端流程**：CLI → 时间解析器 → 数据库层
- **交互设计**：支持智能时间解析，自动计算时长；支持备注字段记录上下文
- **测试标准**：手动测试 CLI 命令功能正常，时间解析准确
- **提交信息**：`feat: add time tracking CLI commands with smart parsing`

### 3 日工时汇总：按天统计工时报表

- **功能目标**：提供按天统计的工时报表，区分 AI 和人工时
- **文件结构**：
  - `src/cli/task.rs`：在 time 报表命令中实现
  - `src/models/time_entry.rs`：添加查询函数
- **接口设计**：
  ```bash
  devboard task time report           # 今日工时报表
  devboard task time report --date 2024-01-15  # 指定日期报表
  ```
- **后端流程**：CLI → 查询时间聚合 → 格式化输出
- **测试标准**：报表数据准确，格式清晰易读
- **提交信息**：`feat: add daily time summary report`

### 4 看板视图：TUI 中的任务 Kanban 板

- **功能目标**：在 TUI 界面中实现看板视图，按任务状态（待办/进行中/评审/完成）展示任务卡片
- **文件结构**：
  - `src/tui/`：新建 TUI 目录
  - `src/tui/mod.rs`：TUI 模块导出
  - `src/tui/kanban.rs`：看板视图实现
  - `src/tui/app.rs`：TUI 应用主结构
- **接口设计**：
  - 使用 ratatui 库构建终端界面
  - 按 F 键切换到看板视图
  - 支持通过箭头键在任务卡片间导航
  - 支持回车键打开任务详情
- **后端流程**：TUI → 核心逻辑层获取任务数据 → 渲染看板视图
- **测试标准**：TUI 能够启动并显示看板视图（手动验证）
- **提交信息**：`feat: add kanban board view to TUI`

### 5 TUI 基础框架：ratatui 界面结构和状态管理

- **功能目标**：建立 TUI 应用的基本结构，包括状态管理、事件循环、视图切换

- **后端流程**：初始化 → 事件循环 → 渲染 → 退出
- **测试标准**：TUI 能够正常启动、响应按键、退出
- **提交信息**：`feat: add TUI application framework`

### 6 数据模型扩展：在 Task 中添加计时相关字段（如总工时）

- **功能目标**：在 Task 结构中添加累计工时字段，方便快速查看任务总工时

  ```rust
      // ... 现有字段
      pub total_time_seconds: i64,  // 新增：累计工时（秒）
  }
  ```
- **数据模型**：在 tasks 表中添加 total_time_seconds 列
- **测试标准**：字段正确读写，工时累计准确
- **提交信息**：`feat: add total time field to Task model`

## 设计核对点

1. 时间追踪模型是否正确关联到任务和用户（AI/Human）
2. 日工时汇总是否正确区分 AI 和人工时
3. 看板视图是否正确根据任务状态分类展示
4. TUI 框架是否支持后续视图扩展（如文档看板、图表视图）
5. 时间记录是否防止并发修改导致的数据不一致
6. CLI 和 TUI 是否共享同一核心逻辑层
