# v0.1.0: 基础架构

## Context
DevBoard 项目的第一个里程碑。从零搭建项目基础架构，实现核心数据模型和 CLI 基础命令。本阶段建立整个项目的技术基础，后续里程碑在此基础上迭代。

版本类型：minor（新功能，首个里程碑）
里程碑起始 ref: b6982f2498960055c77b2d5289df1ae9a393ad01

## 产品边界
本阶段做什么：
- 项目、里程碑、任务的 CRUD 操作
- 三种任务类型（Requirement / Task / Bug）
- 状态流转（待办→进行中→评审→完成）
- SQLite 数据层和 schema 迁移
- CLI 基础命令

本阶段不做什么：
- TUI 界面（v0.2）
- 时间追踪（v0.2）
- 文档功能（v0.3）
- 图表功能（v0.3）
- 同步功能（v0.5）

## 子任务详细设计

### 1 项目初始化

- **功能目标**：搭建 Cargo 项目结构，配置依赖，创建基础模块
- **文件结构**：
  ```
  src/
  ├── main.rs           # 入口，解析 CLI 参数
  ├── cli/
  │   ├── mod.rs        # CLI 模块导出
  │   ├── project.rs    # 项目命令
  │   ├── milestone.rs  # 里程碑命令
  │   └── task.rs       # 任务命令
  ├── db/
  │   ├── mod.rs        # 数据库模块导出
  │   ├── connection.rs # SQLite 连接管理
  │   └── migration.rs  # Schema 迁移
  ├── models/
  │   ├── mod.rs        # 模型导出
  │   ├── project.rs    # Project 模型
  │   ├── milestone.rs  # Milestone 模型
  │   ├── task.rs       # Task 模型
  │   └── time_entry.rs # TimeEntry 模型
  └── error.rs          # 错误类型定义
  ```
- **接口设计**：模块间通过 pub 函数暴露接口
- **测试标准**：`cargo check` 通过
- **提交信息**：`feat: initialize project structure with dependencies`

### 2 数据库层

- **功能目标**：实现 SQLite 连接管理、schema 迁移、基础 CRUD
- **文件结构**：
  - `src/db/connection.rs`：连接池管理，`get_connection()` 返回 `Connection`
  - `src/db/migration.rs`：版本化迁移，`run_migrations()` 执行所有待执行迁移
- **接口设计**：
  ```rust
  pub fn get_connection(db_path: &Path) -> Result<Connection, DbError>
  pub fn run_migrations(conn: &Connection) -> Result<(), DbError>
  ```
- **数据模型**：见 DEVELOPMENT.md 中的 SQL 定义
- **测试标准**：内存数据库测试迁移正确性
- **提交信息**：`feat: add SQLite connection and schema migration`

### 3 数据模型

- **功能目标**：定义 Project / Milestone / Task / TimeEntry 的 Rust 结构体和数据库映射
- **文件结构**：
  - `src/models/project.rs`
  - `src/models/milestone.rs`
  - `src/models/task.rs`
  - `src/models/time_entry.rs`
- **接口设计**：
  ```rust
  // Task 类型
  pub enum TaskType { Requirement, Task, Bug }
  pub enum TaskStatus { Todo, InProgress, Review, Done }
  pub enum TaskPriority { Low, Normal, High, Urgent }
  pub enum Actor { Ai, Human }

  // Task 结构体
  pub struct Task {
      pub id: i64,
      pub project_id: i64,
      pub milestone_id: Option<i64>,
      pub parent_id: Option<i64>,
      pub task_type: TaskType,
      pub title: String,
      pub description: Option<String>,
      pub status: TaskStatus,
      pub priority: TaskPriority,
      pub assignee: Option<String>,
      pub due_date: Option<NaiveDate>,
      pub actor: Actor,
      // Bug 专属
      pub steps_to_reproduce: Option<String>,
      pub severity: Option<String>,
      pub environment: Option<String>,
      // Requirement 专属
      pub user_story: Option<String>,
      pub acceptance_criteria: Option<String>,
      pub created_at: NaiveDateTime,
      pub updated_at: NaiveDateTime,
  }
  ```
- **测试标准**：结构体创建和字段访问正确
- **提交信息**：`feat: define core data models`

### 4 CLI 框架

- **功能目标**：使用 clap 定义 CLI 命令结构，支持子命令路由
- **文件结构**：
  - `src/cli/mod.rs`：CLI 顶层定义
  - `src/main.rs`：解析参数并路由到对应处理函数
- **接口设计**：
  ```rust
  #[derive(Parser)]
  #[command(name = "devboard")]
  struct Cli {
      #[command(subcommand)]
      command: Commands,
  }

  enum Commands {
      Project(ProjectArgs),
      Milestone(MilestoneArgs),
      Task(TaskArgs),
  }
  ```
- **测试标准**：`devboard --help` 输出正确
- **提交信息**：`feat: add CLI framework with clap`

### 5 项目管理 CLI

- **功能目标**：实现 project list / add / update / delete 命令
- **文件结构**：`src/cli/project.rs`
- **接口设计**：
  ```bash
  devboard project list                    # 列出所有项目
  devboard project add "项目名称"           # 创建项目
  devboard project update <id> --name "新名称"  # 更新项目
  devboard project delete <id>             # 删除项目
  ```
- **后端流程**：CLI → 调用 models 层函数 → 执行 SQL → 输出结果
- **测试标准**：内存数据库测试 CRUD 正确性
- **提交信息**：`feat: add project CRUD CLI commands`

### 6 里程碑管理 CLI

- **功能目标**：实现 milestone list / add / update / delete 命令

- **接口设计**：

  ```bash
  devboard milestone list [--project <id>]  # 列出里程碑

  ```
- **测试标准**：内存数据库测试 CRUD 正确性
- **提交信息**：`feat: add milestone CRUD CLI commands`

### 7 任务管理 CLI

- **功能目标**：实现 task list / add / update / delete 命令，支持类型筛选
- **文件结构**：`src/cli/task.rs`
- **接口设计**：
  ```bash
  devboard task list [--project <id>] [--type requirement|task|bug] [--status todo]  # 列出任务
  devboard task add --project <id> --type task "任务标题"  # 创建任务
  devboard task update <id> --status in_progress  # 更新任务
  devboard task delete <id>                 # 删除任务
  ```
- **测试标准**：内存数据库测试 CRUD + 类型筛选正确
- **提交信息**：`feat: add task CRUD CLI commands with type filter`

### 8 状态流转

- **功能目标**：实现 task status 命令，支持状态切换和验证
- **文件结构**：`src/cli/task.rs`（扩展）
- **接口设计**：
  ```bash
  devboard task status <id> in_progress    # 切换到进行中
  devboard task status <id> review         # 切换到评审
  devboard task status <id> done           # 切换到完成
  devboard task status <id> todo           # 重新打开
  ```
- **后端流程**：验证状态流转合法性（不能从完成直接到进行中等）
- **测试标准**：状态流转测试 + 非法流转报错
- **提交信息**：`feat: add task status transition with validation`

## 设计核对点

1. 数据模型是否覆盖产品文档中定义的所有任务属性
2. CLI 命令命名是否遵循 Rust 惯用风格
3. 错误处理是否完整（不使用 unwrap）
4. 数据库 schema 是否支持后续里程碑的功能扩展
5. 模块划分是否清晰，是否便于后续添加 TUI 层
